# 建站元技能 2.0 — 路由决策树

**设计时间**：2026-09-30  
**输入**：三层架构 + 问题契约与行为契约  
**目标**：设计完整的路由决策树，包含 5 种任务类型 × 5 条执行路径

---

## 1. 决策树概览

```mermaid
graph TD
    Start[用户输入] --> Diagnosis[Layer 1: 诊断判断]
    
    Diagnosis --> TaskCard[生成任务卡]
    TaskCard --> Node1{材料完整度?}
    
    Node1 -->|稀疏| PathE[路径 E: 先澄清任务]
    Node1 -->|中等| CheckGaps{有阻塞性缺口?}
    Node1 -->|丰富| Node2
    
    CheckGaps -->|是| AskGaps[提问缺口]
    CheckGaps -->|否| Node2
    AskGaps --> ReDiagnosis[重新诊断]
    ReDiagnosis --> Node2
    
    Node2{任务类型?}
    
    Node2 -->|新项目| Node3A{模式选择?}
    Node2 -->|迭代| Node3B{检查 iterations/?}
    Node2 -->|skill 化| Node3C{问题清晰度?}
    Node2 -->|重构| Node3D{重构范围?}
    Node2 -->|只是想法| PathE
    Node2 -->|超出范围| Reject[告知不适用]
    
    Node3A -->|Batch| PathA_Batch[路径 A-Batch: 快速生成骨架]
    Node3A -->|Interactive| PathA_Interactive[路径 A-Interactive: 逐步引导]
    
    Node3B -->|存在| PathB[路径 B: 迭代现有项目]
    Node3B -->|不存在| Warn[提示可能判断错误]
    Warn --> PathA_Interactive
    
    Node3C -->|高信心| PathC_Direct[路径 C-Direct: 直接制作 skill]
    Node3C -->|低信心| PathC_Clarify[路径 C-Clarify: 先澄清目标]
    
    Node3D -->|局部| PathD_Local[路径 D-Local: 局部重构]
    Node3D -->|全局| PathD_Global[路径 D-Global: 全局重构]
    
    PathE --> JTBD[dbs-jtbd]
    JTBD --> ReDiagnosis2[重新诊断]
    ReDiagnosis2 --> Node2
    
    PathA_Batch --> ExecA_Batch[执行: first-flight batch 模式]
    PathA_Interactive --> ExecA_Int[执行: first-flight 8 步逐步]
    PathB --> ExecB[执行: PRD 迭代 + phases]
    PathC_Direct --> ExecC_Direct[执行: dbs-skill-maker]
    PathC_Clarify --> ExecC_Clarify[执行: dbs-goal + dbs-skill-maker]
    PathD_Local --> ExecD_Local[执行: codebase-design]
    PathD_Global --> ExecD_Global[执行: wayfinder]
    
    ExecA_Batch --> Report[最终汇报]
    ExecA_Int --> Report
    ExecB --> Report
    ExecC_Direct --> Report
    ExecC_Clarify --> Report
    ExecD_Local --> Report
    ExecD_Global --> Report
    
    Reject --> End[结束]
    Report --> End
```

## 2. 决策节点详解

### 节点 1：材料完整度评估

**输入**：任务卡中的材料完整度字段

**判断依据**：
- **丰富**：可指物性 + 情境清晰 + 完成边界 都清楚
- **中等**：3 个维度中有 2 个清楚
- **稀疏**：3 个维度中只有 0-1 个清楚

**分支路径**：
```
稀疏 → 路径 E（先用 dbs-jtbd 澄清任务）
中等 → 检查是否有阻塞性缺口
  ├─ 有缺口 → 提问 → 重新诊断
  └─ 无缺口 → 进入节点 2
丰富 → 直接进入节点 2
```

**示例**：
```
输入 1："做个作品集"
  → 可指物性：✅ 作品集网站
  → 情境清晰：❓ 给谁看？
  → 完成边界：❓ 包含哪些内容？
  → 材料完整度：中等

输入 2："做点东西"
  → 可指物性：❌ 不知道做什么
  → 情境清晰：❌ 不知道场景
  → 完成边界：❌ 不知道边界
  → 材料完整度：稀疏
```

---

### 节点 2：任务类型判断

**输入**：任务卡中的任务类型字段

**判断依据**：
| 任务类型 | 关键词 | 目录状态 | LLM 判断 |
|---------|-------|---------|---------|
| **新项目** | "做个""搭个""想做" | 无 iterations/ | 创建性任务 |
| **迭代** | "加""改""更新" | 有 iterations/ | 增量性任务 |
| **skill 化** | "反复""每次""自动化" | - | 模式提取 |
| **重构** | "优化""重构""改架构" | 有代码 | 结构调整 |
| **只是想法** | "想法""不确定""点子" | - | 探索性 |

**优先级**：
1. 目录状态（最可靠）
2. 关键词匹配（次可靠）
3. LLM 综合判断（兜底）

**分支路径**：
```
新项目 → 节点 3-A（模式选择）
迭代 → 节点 3-B（检查 iterations/）
skill 化 → 节点 3-C（问题清晰度）
重构 → 节点 3-D（重构范围）
只是想法 → 路径 E（先澄清任务）
超出范围 → 告知不适用，结束
```

---

### 节点 3-A：新项目模式选择

**输入**：任务卡中的推荐模式字段

**判断依据**：
```
用户明说"一次性做完" → Batch
材料完整度 = 丰富 + 信心水平 = 高 → 建议 Batch（但默认 Interactive）
其他 → Interactive
```

**分支路径**：
```
Batch → 路径 A-Batch
  skill 序列：first-flight（batch 模式）
  特点：生成 6 份骨架 + TODO 标注，一次性交付

Interactive → 路径 A-Interactive
  skill 序列：first-flight-grill → brief → prd → design → architecture → content → agents → phases
  特点：每步可停，用户参与决策
```

**示例**：
```
输入："做个作品集网站，一次性生成所有文档"
  → 推荐模式：Batch
  → 路径：A-Batch

输入："帮我搭个产品官网"
  → 推荐模式：Interactive（默认）
  → 路径：A-Interactive
```

---

### 节点 3-B：迭代情境检查

**输入**：工作目录状态

**判断依据**：
```bash
# 检查 iterations/ 目录是否存在
if [ -d "iterations/" ]; then
  echo "存在"
else
  echo "不存在"
fi

# 检查 BRIEF.md 是否存在
if [ -f "BRIEF.md" ]; then
  echo "存在"
else
  echo "不存在"
fi
```

**分支路径**：
```
iterations/ 存在 + BRIEF.md 存在 → 路径 B（确认是迭代）
  skill 序列：first-flight-prd（迭代模式）→ first-flight-phases

iterations/ 不存在 → 提示"未检测到 iterations/，可能判断错了"
  → 询问用户"这是首次建站还是迭代？"
  → 用户确认首次 → 切换到路径 A-Interactive
  → 用户确认迭代 → 继续路径 B（但提示"建议先运行 first-flight 创建 BRIEF"）
```

**示例**：
```
输入："给我的网站加个博客功能"
  → 任务类型：迭代
  → 检查目录：iterations/ 存在
  → 路径：B

输入："改一下首页"
  → 任务类型：迭代
  → 检查目录：iterations/ 不存在
  → 提示：可能判断错了
  → 询问用户确认
```

---

### 节点 3-C：skill 化问题清晰度

**输入**：任务卡中的信心水平字段

**判断依据**：
```
信心水平 = 高 → 问题清楚
  特征：
  - 用户给出了反复案例
  - 能清楚描述输入输出
  - 能说出具体痛点

信心水平 = 中/低 → 问题模糊
  特征：
  - 只说"反复遇到"但没具体案例
  - 不确定要解决什么问题
  - 没说清输入输出
```

**分支路径**：
```
高信心 → 路径 C-Direct
  skill 序列：dbs-skill-maker
  特点：直接制作 skill

中/低信心 → 路径 C-Clarify
  skill 序列：dbs-goal → dbs-skill-maker
  特点：先澄清目标，再制作 skill
```

**示例**：
```
输入："每次写 API 文档都要写相同的字段说明（method/path/params/response），能自动化吗？我有 3 个案例"
  → 信心水平：高（有具体案例 + 清楚输入输出）
  → 路径：C-Direct

输入："反复遇到一些任务，想做成 skill"
  → 信心水平：低（没具体案例）
  → 路径：C-Clarify
```

---

### 节点 3-D：重构范围

**输入**：用户描述 + 代码库状态

**判断依据**：
```
局部重构：
  - 影响 1-3 个文件
  - 不改变整体架构
  - 关键词："这个函数""这个组件""局部"

全局重构：
  - 影响多个目录
  - 改变架构模式（如 Redux → Zustand）
  - 关键词："整个项目""架构""全局"
```

**分支路径**：
```
局部 → 路径 D-Local
  skill 序列：codebase-design（局部优化）

全局 → 路径 D-Global
  skill 序列：wayfinder（大型规划）
```

**示例**：
```
输入："把这个 UserProfile 组件拆成更小的组件"
  → 重构范围：局部
  → 路径：D-Local

输入："把整个状态管理从 Redux 改成 Zustand"
  → 重构范围：全局
  → 路径：D-Global
```

---

## 3. 五条执行路径详解

### 路径 A-Batch：快速生成骨架

**触发条件**：
- 任务类型 = 新项目
- 推荐模式 = Batch
- 材料完整度 = 丰富

**执行流程**：
```
1. 调用 first-flight（batch 模式）
   输入：用户描述
   输出：6 份文档骨架（BRIEF / PRD / DESIGN / ARCHITECTURE / CONTENT / AGENTS）
   
2. 标注 TODO
   在每份文档中标注需要用户补充的地方
   
3. 一次性汇报
   展示 6 份文档 + TODO 清单
   询问"要继续实施吗？"
```

**skill 调用伪代码**：
```javascript
await invokeSkill('first-flight', {
  mode: 'batch',
  input: userDescription,
  output: 'root directory'
});

// first-flight 内部会：
// 1. 生成 BRIEF.md（长期纲领 + TODO）
// 2. 生成 PRD.md（首版功能 + TODO）
// 3. 生成 DESIGN.md（视觉风格 + TODO）
// 4. 生成 ARCHITECTURE.md（技术选型 + TODO）
// 5. 生成 CONTENT.md（内容填充 + TODO）
// 6. 生成 AGENTS.md（AI 入口 + TODO）

reportBatch({
  files: [
    'BRIEF.md',
    'PRD.md',
    'DESIGN.md',
    'ARCHITECTURE.md',
    'CONTENT.md',
    'AGENTS.md'
  ],
  todos: extractTodos()
});
```

**优势**：
- 快速：一次生成全部文档
- 完整：覆盖全部规划维度
- 灵活：用户可以自行补充 TODO

**劣势**：
- 质量：骨架可能不够细致
- 参与：用户无法在过程中干预

---

### 路径 A-Interactive：逐步引导

**触发条件**：
- 任务类型 = 新项目
- 推荐模式 = Interactive（默认）

**执行流程**：
```
1. first-flight-grill（问题定义）
   输入：用户描述
   输出：GRILL.md（5 个问题 + 答案）
   汇报："问题定义完成，要继续吗？"
   
2. first-flight-brief（长期纲领）
   输入：GRILL.md
   输出：BRIEF.md
   汇报："长期纲领完成，要继续吗？"
   
3. first-flight-prd（首版 PRD）
   输入：BRIEF.md
   输出：PRD.md
   汇报："PRD 完成，要继续吗？"
   
4. first-flight-design（视觉风格）
   输入：BRIEF.md + PRD.md
   输出：DESIGN.md
   汇报："设计风格完成，要继续吗？"
   
5. first-flight-architecture（技术选型）
   输入：BRIEF.md + PRD.md
   输出：ARCHITECTURE.md
   汇报："技术架构完成，要继续吗？"
   
6. first-flight-content（内容填充）
   输入：所有前序文档
   输出：CONTENT.md
   汇报："内容规划完成，要继续吗？"
   
7. first-flight-agents（AI 入口）
   输入：所有前序文档
   输出：AGENTS.md
   汇报："AI 配置完成，要继续吗？"
   
8. first-flight-phases（分阶段实施）
   输入：所有文档
   输出：执行报告
   汇报："实施完成 🎉"
```

**skill 调用伪代码**：
```javascript
const skills = [
  'first-flight-grill',
  'first-flight-brief',
  'first-flight-prd',
  'first-flight-design',
  'first-flight-architecture',
  'first-flight-content',
  'first-flight-agents',
  'first-flight-phases'
];

for (const skill of skills) {
  const result = await invokeSkill(skill);
  
  report({
    skill: skill,
    output: result.files,
    keyPoints: result.summary
  });
  
  const userResponse = await ask("要继续吗？");
  
  if (userResponse === '停止') {
    break;
  }
}
```

**优势**：
- 质量：每步都充分思考
- 参与：用户可以随时调整方向
- 灵活：可以中途停止

**劣势**：
- 慢：需要多次确认
- 打断：用户需要持续参与

---

### 路径 B：迭代现有项目

**触发条件**：
- 任务类型 = 迭代
- iterations/ 目录存在
- BRIEF.md 存在

**执行流程**：
```
1. 检测已有文件
   读取：BRIEF.md（长期纲领）
   读取：最新版 PRD.md（从 iterations/ 中找）
   
2. first-flight-prd（迭代模式）
   输入：
     - BRIEF.md（长期约束）
     - 上一版 PRD.md（已有功能）
     - 用户新需求
   输出：
     - iterations/v{N}-{slug}/PRD.md（新版 PRD）
   汇报："PRD 完成，要继续吗？"
   
3. first-flight-phases（实施迭代）
   输入：新版 PRD.md
   输出：执行报告
   汇报："迭代完成 🎉"
```

**版本号规则**：
```javascript
// 读取 iterations/ 目录
const versions = fs.readdirSync('iterations/')
  .filter(f => f.startsWith('v'))
  .map(f => parseInt(f.match(/v(\d+)/)[1]));

const latestVersion = Math.max(...versions);
const nextVersion = latestVersion + 1;

// 生成新版本目录
const slug = generateSlug(userFeature); // 如 "blog"
const newDir = `iterations/v${nextVersion}-${slug}`;
```

**skill 调用伪代码**：
```javascript
// Step 1: 读取已有文件
const brief = await readFile('BRIEF.md');
const latestPRD = await findLatestPRD('iterations/');

// Step 2: 生成新版 PRD
const newPRD = await invokeSkill('first-flight-prd', {
  mode: 'iteration',
  brief: brief,
  previousPRD: latestPRD,
  newRequirement: userInput
});

report({
  skill: 'first-flight-prd',
  output: newPRD.path,
  version: newPRD.version,
  changes: newPRD.diff
});

const userResponse = await ask("要继续实施吗？");

if (userResponse === '是') {
  // Step 3: 实施迭代
  await invokeSkill('first-flight-phases', {
    prd: newPRD.path
  });
}
```

**优势**：
- 延续性：尊重 BRIEF 的长期约束
- 可追溯：版本化管理
- 增量：只关注新需求

**劣势**：
- 依赖：必须有 BRIEF 和 iterations/
- 复杂：版本管理增加复杂度

---

### 路径 C-Direct：直接制作 skill

**触发条件**：
- 任务类型 = skill 化
- 信心水平 = 高
- 有反复案例

**执行流程**：
```
1. dbs-skill-maker
   输入：
     - 问题描述
     - 反复案例（至少 2 个）
   输出：
     - ~/.agents/skills/{skill-name}/SKILL.md
     - 验证等级（L1-L3）
   汇报：
     - skill 文件路径
     - 验证等级
     - 使用方法
```

**skill 调用伪代码**：
```javascript
const result = await invokeSkill('dbs-skill-maker', {
  problem: userProblem,
  examples: userExamples
});

report({
  skill: 'dbs-skill-maker',
  output: result.skillPath,
  verificationLevel: result.level, // L1 / L2 / L3
  usage: result.howToUse
});
```

**验证等级说明**：
- **L1（推理验证）**：内部自洽，无明显逻辑错误
- **L2（案例验证）**：通过用户提供的案例测试
- **L3（实战验证）**：在真实场景中使用并确认有效

**优势**：
- 快速：跳过澄清步骤
- 直接：立即生成 skill

**劣势**：
- 风险：如果问题理解错了，生成的 skill 不可用

---

### 路径 C-Clarify：先澄清目标再制作

**触发条件**：
- 任务类型 = skill 化
- 信心水平 = 中/低
- 没有明确案例

**执行流程**：
```
1. dbs-goal（目标澄清）
   输入：用户模糊描述
   输出：目标卡（goal_card.md）
   汇报："目标澄清完成，要继续制作 skill 吗？"
   
2. dbs-skill-maker
   输入：目标卡
   输出：SKILL.md + 验证等级
   汇报："skill 制作完成 🎉"
```

**skill 调用伪代码**：
```javascript
// Step 1: 澄清目标
const goalCard = await invokeSkill('dbs-goal', {
  userInput: userDescription
});

report({
  skill: 'dbs-goal',
  output: goalCard.path,
  maturityScore: goalCard.score // 5 维度评分
});

const userResponse = await ask("目标清楚了吗？要继续制作 skill 吗？");

if (userResponse === '是') {
  // Step 2: 制作 skill
  const skill = await invokeSkill('dbs-skill-maker', {
    goalCard: goalCard.content
  });
  
  report({
    skill: 'dbs-skill-maker',
    output: skill.path,
    verificationLevel: skill.level
  });
}
```

**优势**：
- 准确：先搞清楚要做什么
- 质量：生成的 skill 更可靠

**劣势**：
- 慢：多一个澄清步骤

---

### 路径 D-Local：局部重构

**触发条件**：
- 任务类型 = 重构
- 重构范围 = 局部

**执行流程**：
```
1. codebase-design（局部优化）
   输入：
     - 目标代码位置
     - 重构目标
   输出：
     - 重构计划
     - 修改后的代码
   汇报："重构完成 🎉"
```

**skill 调用伪代码**：
```javascript
const result = await invokeSkill('codebase-design', {
  target: userTarget, // 如 "src/components/UserProfile.tsx"
  goal: userGoal      // 如 "拆成更小的组件"
});

report({
  skill: 'codebase-design',
  changedFiles: result.files,
  plan: result.plan
});
```

---

### 路径 D-Global：全局重构

**触发条件**：
- 任务类型 = 重构
- 重构范围 = 全局

**执行流程**：
```
1. wayfinder（大型规划）
   输入：
     - 当前代码库状态
     - 重构目标
   输出：
     - 分阶段重构计划
     - 风险评估
   汇报："规划完成，要开始执行吗？"
   
2. 执行重构计划
   （可能需要人工参与，不一定全自动）
```

**skill 调用伪代码**：
```javascript
const plan = await invokeSkill('wayfinder', {
  codebase: '.',
  goal: userGoal // 如 "从 Redux 迁移到 Zustand"
});

report({
  skill: 'wayfinder',
```

## 5. 路由决策树实现

### 实现方式 1：if-else 树

```javascript
function selectPath(taskCard) {
  // 节点 1：材料完整度
  if (taskCard.材料完整度 === '稀疏') {
    return PATH_E;
  }
  
  if (taskCard.材料完整度 === '中等' && taskCard.阻塞性缺口.length > 0) {
    return {
      action: 'ASK_GAPS',
      gaps: taskCard.阻塞性缺口,
      then: 'RE_DIAGNOSE'
    };
  }
  
  // 节点 2：任务类型
  switch (taskCard.任务类型) {
    case '新项目':
      // 节点 3-A
      if (taskCard.推荐模式 === 'Batch') {
        return PATH_A_BATCH;
      } else {
        return PATH_A_INTERACTIVE;
      }
    
    case '迭代':
      // 节点 3-B
      if (detectIterationsDir()) {
        return PATH_B;
      } else {
        return {
          action: 'WARN',
          message: '未检测到 iterations/，可能判断错误',
          confirm: '这是首次建站还是迭代？',
          then: {
            '首次': PATH_A_INTERACTIVE,
            '迭代': PATH_B
          }
        };
      }
    
    case 'skill 化':
      // 节点 3-C
      if (taskCard.信心水平 === '高') {
        return PATH_C_DIRECT;
      } else {
        return PATH_C_CLARIFY;
      }
    
    case '重构':
      // 节点 3-D
      if (taskCard.重构范围 === '局部') {
        return PATH_D_LOCAL;
      } else {
        return PATH_D_GLOBAL;
      }
    
    case '只是想法':
      return PATH_E;
    
    default:
      return {
        action: 'REJECT',
        message: '此任务超出 meta-builder 覆盖范围'
      };
  }
}
```

### 实现方式 2：配置驱动

```javascript
const ROUTING_RULES = [
  {
    condition: (card) => card.材料完整度 === '稀疏',
    path: PATH_E,
    reason: '材料稀疏，需要先澄清任务'
  },
  {
    condition: (card) => card.材料完整度 === '中等' && card.阻塞性缺口.length > 0,
    action: 'ASK_GAPS',
    reason: '有阻塞性缺口，需要先提问'
  },
  {
    condition: (card) => card.任务类型 === '新项目' && card.推荐模式 === 'Batch',
    path: PATH_A_BATCH,
    reason: '新项目 + Batch 模式'
  },
  {
    condition: (card) => card.任务类型 === '新项目',
    path: PATH_A_INTERACTIVE,
    reason: '新项目 + Interactive 模式（默认）'
  },
  {
    condition: (card) => card.任务类型 === '迭代' && detectIterationsDir(),
    path: PATH_B,
    reason: '迭代 + 有 iterations/ 目录'
  },
  // ... 更多规则
];

function selectPath(taskCard) {
  for (const rule of ROUTING_RULES) {
    if (rule.condition(taskCard)) {
      return {
        path: rule.path,
        action: rule.action,
        reason: rule.reason
      };
    }
  }
  
  // 默认：告知不适用
  return {
    action: 'REJECT',
    message: '未匹配到任何路径'
  };
}
```

**推荐**：方式 2（配置驱动）
- 更易维护
- 可以动态添加规则
- 便于测试

```javascript
// 避免重复诊断
const diagnosisCache = new Map();

async function diagnose(input) {
  const cacheKey = hash(input);
  
  if (diagnosisCache.has(cacheKey)) {
    return diagnosisCache.get(cacheKey);
  }
  
  const result = await runDiagnosis(input);
  diagnosisCache.set(cacheKey, result);
  
  return result;
}
```
