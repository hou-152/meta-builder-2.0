## 三、问题清单（按优先级排序）

### P0 级问题（阻塞性，必须立即修复）

#### P0-1：PATH_B 缺少 wayfinder skill

**发现样本**：S2, S10  
**错误类型**：B 类（判断过程错误 - 路径定义）  
**位置**：`~/.agents/skills/meta-builder/references/routing.md` 的 PATH_B 定义

**问题描述**：
- 期望：迭代项目应该先调用 `wayfinder` 梳理现有项目脉络，再生成新版 PRD
- 实际：直接跳到 `first-flight-prd`，缺少项目脉络梳理步骤

**影响范围**：
- 所有迭代任务（PATH_B）
- 会导致新版 PRD 缺少对现有项目的理解

**修复方案**：
```javascript
// routing.md 第 203-236 行
'B': {
  执行路径: 'B',
  skill序列: [
    { name: 'wayfinder', 作用: '梳理项目脉络' },  // 新增这一行
    { name: 'first-flight-prd', 作用: '生成新版 PRD', 模式: 'iteration' },
    { name: 'first-flight-phases', 作用: '实施迭代' }
  ],
  传参方式: '文件路径',
  汇报点: '每个 skill 完成后',
  预计耗时: '15-30 分钟'
}
```

**验证方式**：
1. 重新测试 S2 和 S10
2. 确认 skill 序列包含 3 个：wayfinder → first-flight-prd → first-flight-phases

### P1 级问题（影响体验，需要尽快修复）

#### P1-1：PATH_A_BATCH 输出路径不明确

**发现样本**：S7  
**错误类型**：C 类（对外表达不清晰 - 输出路径）  
**位置**：`~/.agents/skills/meta-builder/references/routing.md` 的 PATH_A_BATCH 定义

**问题描述**：
- 期望：明确说明 BRIEF.md 放在根目录，其他文档放在 `iterations/v1-initial/` 下
- 实际：只说"输出 6 份文档"，未明确文件路径结构

**影响范围**：
- 新项目 Batch 模式（PATH_A_BATCH）
- 用户不清楚文件应该放在哪里

**修复方案**：
```javascript
// routing.md 第 177-202 行
'A-Batch': {
  执行路径: 'A-Batch',
  skill序列: [
    {
      name: 'first-flight',
      作用: '批量生成骨架',
      模式: 'batch',
      输入: '用户描述',
      输出: {
        '根目录': ['BRIEF.md'],
        'iterations/v1-initial/': [
          'PRD.md',
          'DESIGN.md',
          'ARCHITECTURE.md',
          'CONTENT.md',
          'AGENTS.md'
        ]
      },
      说明: '所有文档带 TODO 标注'
    }
  ],
  传参方式: '对话上下文',
  汇报点: '整个链完成后',
  预计耗时: '10-15 分钟'
}
```

**验证方式**：
1. 重新测试 S7
2. 确认输出路径结构清晰明确

---

#### P1-2：路由规则优先级不明确

**发现样本**：S8  
**错误类型**：B 类（判断过程 - 规则优先级）  
**位置**：`~/.agents/skills/meta-builder/references/routing.md` 的规则匹配顺序

**问题描述**：
- 期望：skill 化任务优先匹配 skill 化相关规则（C-Direct / C-Clarify）
- 实际：规则列表中"材料稀疏-先澄清"在前面，可能导致 skill 化任务错误进入 PATH_E

**影响范围**：
- skill 化任务（特别是材料稀疏时）
- 可能被错误路由到 PATH_E（dbs-jtbd）而不是 PATH_C_CLARIFY（dbs-goal）

**修复方案**：

**方案 1：调整规则顺序**
```javascript
// routing.md 第 50-142 行
const ROUTING_RULES = [
  // 1. 超出范围（最高优先级）
  { name: '超出范围', ... },
  
  // 2. 任务类型特定规则
  { name: '新项目-Batch模式', ... },
  { name: '新项目-Interactive模式', ... },
  { name: '迭代-有iterations', ... },
  { name: '迭代-无iterations', ... },
  { name: 'skill化-高信心', ... },
  { name: 'skill化-低信心', ... },  // 优先于通用规则
  { name: '重构-局部', ... },
  { name: '重构-全局', ... },
  
  // 3. 通用规则（兜底）
  { name: '材料稀疏-先澄清', ... },
  { name: '中等材料-有缺口', ... },
  { name: '只是想法', ... }
];
```

**方案 2：在 skill 化规则中添加注释**
```javascript
{
  name: 'skill化-低信心',
  condition: (card) => card.任务类型 === 'skill 化',
  path: 'C-Clarify',
  reason: 'skill 化 + 问题模糊',
  note: '即使材料稀疏，skill 化任务也走 C-Clarify，不走 PATH_E'
}
```

**验证方式**：
1. 重新测试 S8（skill 化 + 材料稀疏）
2. 确认路由到 C-Clarify 而不是 PATH_E
